### ADR-001 — اسم المنصة وهويتها
- **المؤكد:** لا اسم معتمد. (`README.md` يحوي «D.Re7-2026» ولا يدل على اسم منصة.)
- **الناقص:** الاسم، الشعار، الدومين.
- **التوصية:** لا توصية. **المالك:** صاحب المشروع. **الحالة:** OPEN.

### ADR-002 — الهيكل القانوني والتقني للشركات والفروع والمستأجرين
- **المشكلة:** كيف تُمثَّل Organization وCompany وBranch، وما حدود العزل.
- **المؤكد (USER-APPROVED):** عزل الشركات والفروع مطلوب.
- **الناقص:** عدد الشركات، هل هي كيانات قانونية منفصلة، هل تتشارك المستخدمين، هل توجد متطلبات عزل تعاقدية.
- **البدائل:**
  - (أ) قاعدة مشتركة ومعرف شركة مفروض في طبقة البيانات: أبسط وأرخص، وخطؤه أخطر.
  - (ب) schema منفصل لكل شركة: عزل أقوى، تعقيد تشغيلي أعلى.
  - (ج) قاعدة منفصلة لكل شركة: أقوى عزل وأعلى تكلفة.
- **التوصية المبدئية (PROPOSED):** (أ) مع فرض طبقة البيانات، وإبقاء (ب) و(ج) خيارين عند متطلب عزل أقوى. لا حسم قبل معرفة عدد الشركات وطبيعتها.
- **الاعتماديات:** ADR-003, ADR-009. **المالك:** المالك + مسؤول الأمن. **الحالة:** OPEN.

### ADR-003 — مزود السحابة والمنطقة وموقع البيانات
- **المؤكد:** الاستضافة سحابية.
- **الناقص:** المزود، المنطقة، قيود إقامة البيانات، الجهات التنظيمية المنطبقة (PDPL وغيرها).
- **البدائل:** مزود عالمي بمنطقة داخل المملكة، أو مزود محلي، أو بنية هجينة.
- **الأثر:** يحدد توفر الخدمات، التكلفة، التعافي، وتوفر مزودي النماذج.
- **التوصية:** لا توصية قبل حسم المتطلبات التنظيمية. استضافة محلية وحدها لا تثبت امتثالًا. **المالك:** المالك + الامتثال. **الحالة:** OPEN.

### ADR-004 — مزودو النماذج وسياسة التبديل
- **المؤكد:** لا مزود معتمد.
- **الناقص:** أين تُعالج البيانات، شروط الاحتفاظ لدى المزود، الميزانية.
- **البدائل:** مزود واحد، مزودان بتبديل، نموذج مستضاف ذاتيًا.
- **التوصية المبدئية:** طبقة تجريد واحدة أمام النماذج تُسجل المزود والإصدار لكل تشغيل، وتمنع إرسال بيانات غير مصنفة. المقارنة بعد ADR-003 وADR-009. **الحالة:** OPEN.

### ADR-005 — مصادر البيانات الرسمية لكل إدارة
- **الناقص:** النظام الرسمي لكل إدارة (محاسبة، مخزون، موارد بشرية…).
- **التوصية:** لا وكيل يعمل على مصدر غير مُسمّى. في G3 تُستخدم بيانات اصطناعية أو ملفات يعتمدها المالك. **الحالة:** BLOCKED (ينتظر قائمة الأنظمة).

### ADR-006 — نطاق استقلالية الوكلاء
- **المؤكد (USER-APPROVED):** تنفيذ تلقائي محدود بعد تعريف السياسات، وفصل الاقتراح/الاعتماد/التنفيذ.
- **البدائل:** مستويات L0 اقتراح فقط · L1 مسودة جاهزة للاعتماد · L2 تنفيذ تلقائي لمهام معتمدة بالاسم.
- **التوصية المبدئية:** البدء بـL0 لكل الوكلاء، والارتقاء لكل مهمة بقرار موثق. **الحالة:** OPEN.

### ADR-007 — مصفوفة الأدوار والصلاحيات والموافقات
- **الناقص:** الأدوار الفعلية، أصحاب الصلاحية، حدود المبالغ (**UNKNOWN**، لن أخترع أرقامًا).
- **المطلوب لحسمها:** قائمة المناصب، وسياسة التفويض الحالية، وحدود الاعتماد لكل نوع معاملة.
- **التوصية:** الإطار العام في `06`. **الحالة:** OPEN.

### ADR-008 — الأنظمة الخارجية والتكاملات الفعلية
- **الناقص:** أسماء الأنظمة وطرق الوصول (API/تصدير ملفات).
- **التوصية:** تكامل قراءة فقط أولًا. لا اتصال بنظام حقيقي قبل G4 وتصريح مستقل. **الحالة:** BLOCKED.

### ADR-009 — تصنيف البيانات والاحتفاظ والحذف
- **الناقص:** سياسة تصنيف المؤسسة، مدد الاحتفاظ النظامية.
- **التوصية المبدئية:** مستويات مثل عام / داخلي / سري / مقيّد (حساس: موظفون ومالية)، وتحدد المؤسسة أسماءها ومددها. حذف المستخدم يكون بتعطيل مع إبقاء السجلات الرقابية. **الحالة:** OPEN.

### ADR-010 — أهداف الاستعادة والتعافي
- **الناقص:** RTO وRPO لكل خدمة. **التوصية:** لا أرقام قبل تحديد الأثر التجاري. **الحالة:** OPEN.

### ADR-011 — الميزانية والتكلفة التشغيلية
- **الناقص:** سقف شهري، وسياسة الحصص لكل وكيل/شركة. **التوصية:** حصص إلزامية وتنبيهات قبل البدء بأي تشغيل حقيقي. **الحالة:** OPEN.

### ADR-012 — المهام المسموح تنفيذها تلقائيًا
- **التوصية المبدئية:** القائمة فارغة افتراضيًا. تُضاف كل مهمة بقرار منفصل يحدد: الشرط، الحد الأقصى، الأثر الخارجي، طريقة التراجع. **الحالة:** OPEN.

### ADR-013 — مراجعة الأمن والقبول المحاسبي المستقل
- **الناقص:** من يراجع، وبأي معيار فحص. **التوصية:** جهة مستقلة عن فريق البناء قبل G5. **الحالة:** OPEN.

### ADR-014 — صلاحيات بيانات الموظفين والبيانات الحساسة
- **التوصية المبدئية:** عزل بيانات HR بنطاق منفصل، ولا يُرسل شيء منها للنموذج دون سياسة صريحة، ولا قرار وظيفي مستقل من الوكيل. **الحالة:** OPEN.

### ADR-015 — التشغيل والدعم والاستجابة للحوادث
- **الناقص:** فريق التشغيل ومناوباته وSLA. **الحالة:** OPEN.

### ADR-016 (جديد) — موقع مستودع المنصة
- **المشكلة:** المستودع الحالي يحوي لوحات مبيعات فقط. **البدائل:** (أ) نفس المستودع، (ب) مستودع جديد. **التوصية:** (ب) لفصل دورة الحياة والصلاحيات. حتى القرار، الوثائق في `docs/platform-design/` هنا. **الحالة:** OPEN.

### ADR-017 (جديد) — مصير لوحات المبيعات الحالية
- **البدائل:** تبقى مستقلة · تُستخدم كمرجع واجهة · تُدمج لاحقًا. **التوصية:** تبقى مستقلة ومرجعًا. **ملاحظة:** لم يُتحقق أن بياناتها حقيقية. **الحالة:** OPEN.
